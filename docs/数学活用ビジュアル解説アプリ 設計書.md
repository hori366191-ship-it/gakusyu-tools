# 数学活用ビジュアル解説アプリ 設計書（AIエージェント向け）

本ドキュメントは、中高生向けに「数学の各単元が現実世界でどのように活用されているか」を2Dアニメーションと機械音声で直感的に解説するHTMLアプリケーションの設計仕様書である。AI開発エージェントが本仕様に基づき、一貫したデザイン・アーキテクチャでプロトタイプおよび本実装を行えるよう、要件・技術選定・データ構造・コンテンツ仕様を定義する。

---

## 1. プロジェクト概要

### 1.1 コンセプト
* **目的:** 「数学はテストのための計算練習」と感じがちな中学生・高校生に対し、各単元の本質と現実世界での活用事例（身近な体験から最先端技術まで）を視覚的・聴覚的にわかりやすく伝える。
* **表現スタイル:** 上質な紙のノートに万年筆やインクペンで描きながら解説するような、**乳白色の背景＋墨色の2D線画アニメーション**と**機械音声（TTS）によるナレーション**を組み合わせる。
* **HTMLアプリならではの価値:** 動画視聴の一方通行にとどまらず、解説の合間にユーザーがスライダーやドラッグ操作で数値を動かし、グラフや現象の変化を体感できる**「インタラクティブ体験区間」**を組み込む。
* **拡張性:** 最初の単元として**「微分」**を実装するが、将来的には「積分」「三角関数」「ベクトル」「確率・統計」などの単元を容易に追加できる**シナリオ駆動型アーキテクチャ**を採用する。

### 1.2 ターゲットユーザー
* **メインターゲット:** 中学生〜高校生（数式の厳密な証明よりも、直感的なイメージと「なぜ学ぶのか」の納得感を重視する層）。
* **利用環境:** PC・タブレット・スマートフォンのモダンWebブラウザ（Chrome, Safari, Edge, Firefox）。

## 2. デザインシステム・ビジュアルガイドライン

AIエージェントは、すべての描画およびUI実装において以下のデザインルールを厳守すること。

### 2.1 カラーパレット
純白（`#FFFFFF`）および純黒（`#000000`）の直接使用は避け、目に優しい温かみのある配色とする。アクセントカラーは数学的な重要要素にのみ限定使用する。

| 役割 | カラー名 | HEXコード | 用途 |
| :--- | :--- | :--- | :--- |
| **背景（メイン）** | 乳白色（Warm Cream） | `#F7F4EC` | キャンバス全体・ページ背景 |
| **背景（UIパネル）** | 生成り（Soft Paper） | `#EFECE2` | コントロールバー、字幕ボックス、操作パネル |
| **メイン線・文字** | 墨色（Sumi Ink） | `#222222` | 基本の線画、グラフの曲線、本文テキスト |
| **補助線・グリッド** | 薄墨（Light Ink） | `#8C8980` | 座標軸の目盛り、補助線、非アクティブ要素 |
| **アクセント1（強調）** | 朱色（Vermilion） | `#D94E41` | 接線、極値（傾き $0$ の点）、変化率の矢印、現在位置 |
| **アクセント2（補足）** | 藍色（Indigo） | `#2B5B84` | 比較用の平均変化率、インタラクティブ操作ハンドル、ボタン |

### 2.2 タイポグラフィ
* **基本フォント:** 視認性が高く、線画の雰囲気に馴染む明朝系または丸みのあるゴシック系（例: `"Zen Maru Gothic"`, `"Klee One"`, `"Noto Sans JP"`, `sans-serif`）。
* **数式・数値:** 等幅または数学書体（例: `"KaTeX_Main"`, `"Times New Roman"`, `serif`）。
* **字幕サイズ:** 画面幅に応じてレスポンシブに調整（PCで `18px`〜`22px`、モバイルで `14px`〜`16px` 相当）。

### 2.3 2D線画・アニメーション原則
* **描画タッチ:** 均一すぎる無機質な線だけでなく、必要に応じてペンで描くような開始・終了のアニメーション（線が始点から終点へスッと伸びる演出）を基本とする。
* **イージング:** 直線的な `linear` 移動は避け、`easeOutCubic` や `easeInOutQuad` 等の自然な加減速を適用する。
* **情報量の制限:** 1シーンあたり画面上に同時表示する要素は最大3〜4グループまでとし、余白（乳白色エリア）を最低30%以上確保する。

## 3. システムアーキテクチャ・技術構成

### 3.1 技術スタック方針
* **フロントエンド:** HTML5 / CSS3 / Vanilla JavaScript (ES6+) ※必要に応じて単一HTMLファイルでのビルド・実行が可能な構成を優先する。
* **描画エンジン:**
  * **HTML5 Canvas (2D Context):** リアルタイムな関数グラフ描画、ズームイン演出、物理挙動、ドラッグ連動のインタラクティブ表現を担当（高DPI/Retina対応として `window.devicePixelRatio` を必ず考慮すること）。
  * **SVG（任意・併用可）:** アイコンや固定イラストのパスアニメーション（`stroke-dashoffset`）に使用可。ただし単一ファイルでの統一管理を重視する場合はCanvas統一を推奨する。
* **音声エンジン（TTS抽象化レイヤー）:**
  * 音声再生機能は `AudioEngine` クラスとして抽象化し、以下の2モードを切り替え可能にする。
    1. **Web Speech API モード（初期プロトタイプ・開発用）:** `window.speechSynthesis` を利用し、`ja-JP` の音声でテキストを読み上げる。
    2. **プリレンダー音声モード（本番・高品質版用）:** VOICEVOX等で事前生成した `.mp3` / `.wav` ファイルを読み込み、タイムスタンプ同期再生する。
  * **フォールバック仕様:** ブラウザが音声合成に非対応、またはミュート状態の場合でも、文字数に応じた自動待機時間（例: 日本語1文字あたり約 `150ms` + 句読点バッファ）で進行する「字幕タイマーモード」へ自動フォールバックすること。

### 3.2 モジュール構成（論理設計）

```text
Application
├── Core Engine
│   ├── StageRenderer      # Canvas描画・座標変換・手描き風ライン描画・ズーム制御
│   ├── TimelineController # シーン再生・一時停止・シーク・インタラクティブ区間での自動停止
│   ├── AudioEngine        # Web Speech API / 音声ファイル再生 / 字幕同期 / フォールバック
│   └── InteractionManager # マウス・タッチイベント（ドラッグ、スライダー）とCanvas状態の同期
├── UI Components
│   ├── HeaderBar          # 単元タイトル、単元選択メニュー（将来拡張用）
│   ├── SubtitleOverlay    # 現在のナレーション字幕表示
│   ├── InteractivePanel   # 演習区間でのみ表示される操作UI（スライダー、リセット等）
│   └── PlaybackControls   # 再生/一時停止、前/次のシーン、進捗バー、読み上げ速度・音量調整
└── Content Data (JSON / JS Modules)
    └── units/
        ├── differentiation.js  # 第1弾：微分シナリオデータ
        └── (future_units...)   # 第2弾以降：積分、確率、ベクトル等
```

## 4. 画面UI / UX設計

### 4.1 レイアウト構造
16:9のアスペクト比を基準としたメインステージを中央に配置し、モバイル画面でも破綻しないレスポンシブ設計とする。

```text
+-------------------------------------------------------------------+
| [単元: 微分 - 世界の変化を読み解くレンズ]   [目次] [速度:1.0x] [音] |  <- HeaderBar
+-------------------------------------------------------------------+
|                                                                   |
|                                                                   |
|                    2D 乳白色アニメーションステージ                  |  <- StageCanvas
|                  （黒線画 + 朱色/藍色のアクセント）                 |     (主役エリア)
|                                                                   |
|   +-----------------------------------------------------------+   |
|   | [インタラクティブ操作UI] ※体験シーンでのみフェードイン表示   |   |  <- InteractivePanel
|   +-----------------------------------------------------------+   |
+-------------------------------------------------------------------+
| 「曲線をぐっと拡大すると、まっすぐな線に見えてきます。」             |  <- SubtitleOverlay
+-------------------------------------------------------------------+
| [▶/⏸] [◀前へ] [次へ▶]  ====●================  Scene 2 / 6       |  <- PlaybackControls
+-------------------------------------------------------------------+
```

### 4.2 ユーザー操作フロー（解説 ⇄ 体験の切り替え）
1. **自動再生モード（解説）:** シーン内のステップごとに音声読み上げと線画アニメーションが同期して進行する。
2. **体験停止（インタラクティブ区間）:** 特定のステップに到達すると再生が一時停止し、「自分で動かしてみよう！」のガイドと操作UI（ドラッグ可能な点やスライダー）が有効化される。
3. **再開:** ユーザーが操作を終えて「解説を続ける」ボタンを押すと、次の解説ステップへスムーズに移行する。
4. **ブラウザの自動再生制限対策:** 初回アクセス時はタイトルオーバーレイ（例：「微分の世界をはじめる」ボタン）を表示し、ユーザーのクリックイベントを起点に音声エンジンを初期化する。

## 6. 第1弾コンテンツ詳細仕様：「微分」

第1弾は全6シーン（合計再生時間：約5〜6分）で構成する。数式の計算テクニックではなく、**「変化の勢い（傾き）を捉える力」**が現実世界でどう機能しているかを段階的に伝える。

### シーン構成一覧

| Scene | タイトル | 伝えるべき核（コアメッセージ） | 主な2Dアニメーション演出 | インタラクティブ体験 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **導入：「瞬間」を測る不思議** | 「平均の速さ」と「今この瞬間の速さ」は違う。微分は変化の勢いを切り取る虫眼鏡である。 | 走る車の線画とスピードメーターを描画。$1\text{時間で}60\text{km}$ 進んだ記録と、刻々と針が振れるメーターを比較表示する。 | なし（導入テンポ重視） |
| **2** | **本質：曲線を拡大すると直線になる** | どんな曲線も極限まで拡大すると直線（接線）になる。その傾きが瞬間の変化率（微分係数）である。 | 放物線 $y = x^2$ を描き、点 $(1, 1)$ へ連続ズームイン。曲線が朱色の接線と重なる様子を見せる。幅 $\Delta x \to 0$ のイメージを視覚化。 | **【体験1】** ズーム倍率スライダー、および点 $x$ をドラッグして接線の傾き $2x$ がリアルタイムに変わる実験。 |
| **3** | **身近な活用：ゲームとUIの滑らかな動き** | スマホのスクロールやゲームのジャンプが心地よいのは、毎瞬間の速度（微分）が滑らかに制御されているから。 | キャラクターがジャンプする軌跡（位置のグラフ）と、その真下に速度メーター（微分のグラフ）を連動描画。等速運動のギクシャク感と、加速度のある滑らかな動きを比較。 | **【体験2】** 「重力」や「初速度」を変えてジャンプ軌跡と速度変化を見比べるミニ操作（任意/簡易スライダー）。 |
| **4** | **社会での活用：「一番いい場所」を探す（最適化）** | 山の頂上や谷底では、接線の傾きがちょうど $0$ になる。これがビジネスや設計の「ベストアンサー探し」に使われる。 | 「商品の価格 vs 利益」の放物線グラフ、および「1枚の紙から作る容積最大の箱」の展開図を描画。頂点で朱色の接線が水平（傾き $= 0$）になり、ピタッと光る演出。 | **【体験3】** 価格スライダーを動かし、利益が最大になる点（傾き $= 0$ の場所）を自分の手で探すミニゲーム。 |
| **5** | **高度な活用：AIの学習とロケット制御** | 複雑なAIの学習も、宇宙ロケットの姿勢制御も、「今の傾きから次の一歩を決める」微分の応用である。 | **① AI（勾配降下法）:** 霧に包まれた谷の地形図を描き、ボールが足元の傾き（朱色の矢印）を頼りに一番低い誤差の谷底へ転がり落ちる演出。<br>**② ロケット制御:** 風でわずかに傾いたロケットが、傾きの勢いを検知して逆噴射で姿勢を戻す線画アニメ。 | なし（視覚的インパクトとスケール感の提示） |
| **6** | **まとめ：未来を予測する道具** | 「今この瞬間の変化」がわかれば、「ほんの少し先の未来」が予測できる。微分は世界を読み解く強力なレンズである。 | これまでのアイコン（車、接線、ゲーム、箱、AIの谷、ロケット）が1本の滑らかな曲線で結ばれ、接線が未来方向へスッと伸びてタイトルロゴに戻る。 | 終了メニュー（もう一度見る / 特定のシーンへジャンプ） |

### ナレーション作成ガイドライン（AIエージェント向け）
* 1ステップのセリフは**40〜70文字程度**に収め、機械音声で聞き取りやすい短い文節に区切る。
* 難しい専門用語（例：「極限」「導関数」「勾配降下法」）を出す場合は、必ず直前または直後に日常的な比喩（「虫眼鏡で拡大する」「坂の急さ」「谷底へ下るコンパス」）を添える。
* 読み間違いを防ぐため、TTSに渡すテキストと画面表示用の字幕テキストを分離できる構造（例: `subtitle` と `speechText` の併用）を許容する。

## 7. 非機能要件・実装規約

### 7.1 描画パフォーマンスとレスポンシブ
* アニメーションループは `requestAnimationFrame` を使用し、フレームレート差を吸収するため必ずデルタタイム（`dt`）ベースで進行計算を行う。
* ウィンドウリサイズ時はデバウンス処理を入れつつCanvas解像度を再計算し、線画がぼやけないようにする。

### 7.2 音声（Web Speech API）の堅牢性
* 一部のブラウザ（Chrome等）では長文読み上げ時に `onend` イベントが発火しないバグや停止現象が知られているため、1ステップを短文に保つとともに、タイムアウトによる安全進行ガードを実装すること。
* シーンをスキップ・一時停止した際は、即座に `window.speechSynthesis.cancel()` を呼び出し、音声の重複を防ぐこと。

### 7.3 アクセシビリティ
* 音声が聞けない環境でも完全に理解できるよう、字幕はデフォルトONとし、視覚的なハイライト（朱色の線やラベル）だけで話の要点が追える設計にする。
* 主要コントロール（再生/一時停止、前後シーン移動）はキーボード操作（`Space`, `ArrowLeft`, `ArrowRight`）にも対応させる。

## 8. 開発フェーズとAIエージェントへの実装タスク指針

実装は以下のフェーズ順に進めること。最初から全機能を一度に書かず、各フェーズで動作確認可能な成果物を出力する。

### Phase 1: MVPプロトタイプ（単一HTMLファイル）
* **スコープ:** 乳白色＋墨色のCanvasエンジン、Web Speech API連携、字幕表示、および**Scene 1〜Scene 2（放物線のズームイン＋接線ドラッグ体験）**のみを実装。
* **検証項目:** 手描き風線画の視認性、ズームアニメーションの滑らかさ、音声と描画の同期感、インタラクティブ体験の操作性。

### Phase 2: エンジン整備とUI完成
* **スコープ:** シナリオデータ駆動の構造へリファクタリング。再生バー、目次ジャンプ、速度変更、ミュート時のタイマー自動進行フォールバックを実装。

### Phase 3: 第1弾「微分」全6シーンの本実装
* **スコープ:** Scene 3（ゲーム動き）、Scene 4（最適化ミニゲーム）、Scene 5（AI勾配降下法・ロケット）、Scene 6（まとめ）の描画モジュールとナレーションデータをすべて実装。

### Phase 4: 音声品質向上と他単元拡張の準備
* **スコープ:** `AudioEngine` に事前生成音声ファイル（VOICEVOX等）の再生モードを追加。単元選択メニューを有効化し、第2弾（例：積分・三角関数）をJSON/JSモジュール追加のみで展開できる状態にする。
